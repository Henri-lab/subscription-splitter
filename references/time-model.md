# 六个概念的时间模型（time model）

> 本技能的地基。判断任何"该不该拆、怎么建模"之前，先回答：**它活在哪个时间？**

## 1. 六个概念，按时间分类

```
        过去（不可变事实）      现在（可变授权）       未来（承诺/负债/触发器）
            │                    │                     │
 ┌──────────┼────────────────────┼─────────────────────┼──────────┐
 │  订单        权益              订阅（触发器）         积分       │
 │  支付        会员（权益的包）                         │          │
 │  (事实源⭐)  (派生数据)                             (负债⭐)    │
 └────────────────────────────────────────────────────────────────┘
```

| 概念 | 本质 | 一句话 | 时间属性 |
| --- | --- | --- | --- |
| 订单 | 交易的承诺凭证 | "A 答应给 B 钱，B 答应给 A 货" | 过去，追加不可改 |
| 支付 | 订单的履行事实 | "钱真的动了"（一单可多笔：定金+尾款） | 过去，追加不可改 |
| 权益 | 授权事实：此刻被允许做什么 | "能看 VIP 视频、能进会员区" | 现在，由过去推导 |
| 会员 | 权益的打包容器 + 身份标签 | "用户挂着 VIP 身份，附带一堆权益" | 现在，派生数据 |
| 订阅 | 周期性制造订单的机器 | "每月 1 号自动产生扣款订单 + 延长权益" | 未来，计划/触发器 |
| 积分 | 企业欠用户的债 | "500 分 = 你欠他价值 5 元的给付" | 未来索取权，账本即事实源 |

## 2. 洞察一：权益和会员是派生数据，订单流水才是事实源

> Kleppmann：表状态是派生数据，日志才是事实源。

```
事实源（不可变）：orders + payments 流水
        │ 推导（可随时重跑）
        ▼
派生数据（可变）：memberships + entitlements 当前状态
```

"用户是不是会员"的答案：**不是查 memberships 表，而是把订单+支付流水重放一遍算出来**。
memberships 只是缓存/物化视图——删了可从订单重建；订单流水删了才是真丢数据。

对应判据：**删表重建测试**（quality-gate-builder / membership 的 D-1）。

## 3. 洞察二：积分是唯一的"另一个事实源"，性质是负债

> Helland：会计不用橡皮擦（用了会坐牢）。过期是追加 `expired` 流水，不是 DELETE。

| | 订单/支付 | 积分 |
| --- | --- | --- |
| 语义 | 钱收到了，企业资产增加 | 欠用户的债，每发一分 = 多一笔负债 |
| 处置 | 事实追加 | 负债核销（追加负向条目） |
| 过期 | 订单无需"过期动作" | 每一分过期 = 一笔负债核销，必须记账 |

**会员是状态，积分是账**——状态可以覆盖，账只能追加。这是 INV-14（账本不可变）更深一层的理由。

## 4. 洞察三：订阅不是"东西"，是订单的自动化发生器

```
手动：用户点购买 → 产生订单 ─┐
                             ├→ 订单 → 支付 → 权益授予（同一条管道）
订阅：到点了 → 系统自动产生订单 ┘
```

订阅 ≠ 一种会员；订阅 = "定时产生订单"的调度策略 + "权益自动续期"的策略组合：

- 定时任务扫描到期订阅 → 调用与普通购买**相同**的下单流程；
- 策略代码决定：到期前 N 天提醒？宽限期几天？扣款失败降级还是断？

同一套订单+支付+权益管道，喂两种入口（人手点 / 机器点）——这就是它不需要独立服务的原因：
它是管道上的"自动水龙头"（对齐 L-002 模块化单体 + Helland 实体/活动）。

## 5. 与协议锚点的映射

| 概念 | MSP / ASP 锚点 |
| --- | --- |
| 订单 | INV-2 快照、INV-31 支付意图上限 |
| 支付 | INV-6/7 唯一写入口 + 幂等、INV-20 金额一致 |
| 权益 | INV-3 单一判权源、INV-9 续期单调、INV-26 按 source 幂等 |
| 会员 | 权益的打包视图（判权仍走 Entitlement） |
| 订阅 | OP-E2、INV-9/26、reminder-contract（到期提醒策略） |
| 积分 | ledger L1/L2/L4、INV-13/14/15 |

## 6. 一条时间线串起来

```yaml
T0 下单              orders: created          # 承诺
T1 支付成功           payments: success        # 履行事实
T2 同一事务内         entitlements: VIP ✅     # 授权（派生自 T1）
                     memberships: VIP 至 11-15 # 权益打包
                     point_tx: +50             # 负债记账
T3 每天             查询权益有效期，越过即拒      # 状态型数据，无事件
──── 30 天后 ────
T4 订阅触发器        自动产生新订单             # 订阅 = 造单机器
T5 自动扣款成功       payments                 # 履行
T6 事务内            entitlements 延长 30 天    # 授权刷新
   扣款失败          策略：宽限 → 降级 → 到期失效  # 策略决策
```

每一格都是分类的实例：事实追加（T1/T5）、派生刷新（T2/T6）、负债记账（T2）、未来触发（T4）、策略决策（T6 失败分支）。
